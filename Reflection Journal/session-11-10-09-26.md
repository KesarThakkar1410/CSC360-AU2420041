## Session Content

This session felt like an important transition in the course because we are now moving from computer graphics towards image processing. Until now, a major focus of the course has been understanding how graphics can be created and represented using code. Image processing introduces a slightly different perspective, where we work with existing images and try to analyse, modify, or extract information from them.

At the beginning of the session, we were introduced to the next textbook, *Core Java Volume II*. The professor discussed some of the upcoming areas such as streams, networking, database connectivity, and concurrency. This gave me an idea of how the course will gradually move towards more advanced Java concepts.

One of the most interesting discussions was about downloading versus streaming. When a file is downloaded, the complete content is generally received before we use it. Streaming works differently because the content is delivered continuously in smaller portions while it is being played. The consistency of packet delivery becomes important here. Even if the average network speed is good, irregular delivery can cause the buffer to run low and result in pauses or reduced quality. This helped me understand why average speed alone does not always describe the quality of a network connection.

We then discussed the relationship between XML and vector graphics. SVG, or Scalable Vector Graphics, uses XML to describe graphical objects. Instead of storing an image as a collection of pixels, it can describe shapes such as circles and rectangles along with their positions, dimensions, and other properties. This connected well with our earlier discussions about vector graphics because the mathematical description of an object is actually represented in a file using structured text.

Another major topic was Server-Side Rendering and Client-Side Rendering. In SSR, the server prepares the rendered content and sends it to the client. In CSR, the client receives the necessary files and performs more of the rendering itself. Both approaches have different advantages. SSR can provide a faster initial display and can be useful for content-oriented websites, while CSR can make interactive applications feel more responsive after the initial loading process.

The session also introduced ways of storing graphics. Smaller numbers of images can be stored using traditional databases, either as binary data or by storing references to files. However, when an application has to handle a very large number of high-resolution files, object storage services such as Amazon S3 and Google Cloud Storage become more suitable.

Finally, we discussed AWT, or Abstract Window Toolkit. I found the meaning behind the name interesting because AWT provides an abstraction over the operating system's native windowing system. This allows Java programmers to work with GUI components without having to handle every operating-system-specific implementation themselves.

## Mathematical Concepts

The statistics portion of the session introduced several measures that are useful for understanding data.

### Mean

The mean represents the average value of a dataset. For a population, the values are added together and divided by the total number of values. For a sample, the same general idea is used, but it is calculated over the observations included in the sample.

### Mode

The mode is the value that occurs most frequently in a dataset. A dataset can have one mode or multiple modes, depending on how frequently its values occur.

### Median

The median represents the middle of a sorted dataset. If there is an odd number of observations, it is the middle value. If there is an even number, the two middle values are averaged.

For example, if the values are `[2, 5, 8, 10, 15]`, the median is `8`. If the values are `[2, 5, 8, 10]`, the median becomes `(5 + 8) / 2 = 6.5`.

I also understood why median can sometimes be more useful than mean. If a dataset contains an unusually large or small value, the mean can shift considerably, whereas the median is less affected.

### Variance

Variance tells us how much the values in a dataset differ from the mean. A smaller variance means that the values are relatively close together, while a larger variance indicates greater spread.

This concept became more meaningful when it was connected to streaming. If packet arrival times vary significantly, the streaming experience can become unstable even when the average delivery rate seems acceptable.

### Standard Deviation

Standard deviation is obtained by taking the square root of variance. One benefit of standard deviation is that it is expressed in the same units as the original data, which makes the amount of variation easier to understand.

The connection between standard deviation and network consistency helped me see that these statistical concepts are not only theoretical calculations but can also describe real systems.

## Real-World Applications Explored

The statistics discussion has a clear application in online gaming and video streaming. For example, a player may have a low average ping but still experience lag if the connection frequently fluctuates. In the same way, a streaming service can experience buffering when data does not arrive consistently.

SVG is also commonly used in websites for logos, icons, illustrations, and other scalable graphics. Since it is based on descriptions of shapes rather than a fixed pixel grid, the same graphic can be displayed at different sizes without becoming pixelated.

SSR and CSR can be seen in modern websites as well. Some websites need their content to appear quickly and be easily accessible to search engines, while highly interactive applications may rely more heavily on client-side rendering. The choice depends on what the application is trying to achieve.
