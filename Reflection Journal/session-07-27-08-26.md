## Session Reflection

In today's session we learned topics related to how Java projects are built, tested, and managed. We first discussed what happens when Java code is compiled. I learned that `.java` files are converted into `.class` files containing bytecode, which can then be packaged into a JAR file. We also discussed why compiled files and other generated files should not be pushed to Git, since the repository should mainly contain the source code and project configuration.

We then continued with Maven and the `pom.xml` file. I understood that Maven can automate different parts of the build process, including compiling the code, managing dependencies, and creating the final package. This made me realise how build tools can make projects easier to manage, especially when multiple people are working on the same project.

Another topic discussed in today's session was character encoding, especially UTF-8 and UTF-16. I understood that UTF-8 is widely used as it works well with ASCII and avoids some of the byte-order issues associated with UTF-16. We also discussed unit testing and integration testing. The difference became clear to me when I thought of unit testing as checking individual parts of a program, while integration testing checks whether different parts work correctly together.

Towards the end of the session, we discussed authentication, session management, and technical interviews. The interview discussion stood out to me as the idea of first creating a small Proof of Concept before trying to build a complete solution seems useful beyond interviews as well. 

Overall, this session helped me understand that software development involves much more than writing code. Building, testing, security, and communication are all important parts of creating a reliable application.
