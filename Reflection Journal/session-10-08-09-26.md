## Session Content

The session started with an overview of the textbooks prescribed for the course. The instructor explained the purpose of the different books and which topics we should refer to from each one. This was very useful as instead of treating all the books equally relevant for each and every topic, now I have a better idea of how to use them according to what we are learning.

We then discussed selected chapters from *Core Java Volume I*. Chapter 7 focused on exceptions, assertions, and logging, which are important for identifying and handling problems that occur during program execution. Chapter 8 introduced generic programming. I understood generics as a way to make code reusable across different data types while maintaining type safety. We also discussed the Java Collections Framework in Chapter 9, including structures such as Lists, Sets, Queues, and Maps. Another concept that we discussed was providing access to data without allowing modification, which can be achieved with unmodifiable views.

The next part of the session focused on events in computer graphics and JavaFX. This was more difficult for me because I had previously thought of an event as something that happens and is immediately handled by a particular component. In JavaFX, however, events move through the scene graph. They first travel from the root towards the target and then move back from the target towards the root. These are known as the capturing and bubbling phases. Event filters are involved during the capturing phase, while event handlers work during the bubbling phase.

After that, we discussed layouts and grids. The main idea I took from this part was that a user interface should be able to adjust when the size of the window changes. JavaFX containers such as `GridPane`, `VBox`, and `HBox` help arrange components according to the available space.

We also looked at different UI components and their purposes. A checkbox is suitable when multiple independent options can be selected, whereas radio buttons are used when only one option from a group should be selected. Sliders are useful when users need approximate control, such as changing volume or brightness. Dialog boxes, on the other hand, are useful when the application needs the user to make a decision or acknowledge something before continuing.

Towards the end of the session, we discussed Groups 9 to 12. These included combining Swing and JavaFX components, creating a Master-Detail layout, changing the properties of a graphical object interactively, and connecting JavaFX with a browser DOM using WebView and WebEngine. The last topic was particularly interesting because it showed how different technologies can interact within the same application.

The distinction between capturing and bubbling, along with the difference between event filters and event handlers, made the concept more complicated. I also found the idea of an event being consumed interesting because it means that the event may stop travelling further through the hierarchy.

I think I will understand this better when I implement a JavaFX application with multiple nested components. For now, I can remember the basic flow, but I would need some practical examples to become completely comfortable with it.

## Real-World Applications Explored

Many of the UI concepts from this session can be seen in applications that I use regularly. For example, sliders are commonly used for video progress, volume, brightness, and similar controls. In these situations, users usually care more about moving towards the desired value than entering an exact number.

Radio buttons and checkboxes can also be seen in forms and settings pages. For example, a form may use checkboxes when several preferences can be selected, while radio buttons can be used when only one option is allowed.

The Master-Detail layout is another pattern that appears frequently. Email applications are a good example: one part of the interface displays a list of messages, and selecting one message displays its complete contents separately. This avoids displaying every piece of information at the same time and makes the interface easier to navigate.

## Insights

The part involving JavaFX and WebView was probably the most interesting concept for me. The idea that a JavaFX application can contain a browser and interact with elements of the browser's DOM shows how different technologies can be connected.

It also changed the way I think about graphical applications. Earlier, I mostly considered a GUI as buttons, text fields, menus, and layouts. This session showed me that a GUI can also interact with other environments and respond to events in a much more structured way.

Another important insight for me was that good UI design is not only about appearance. The behaviour of a component and the type of interaction it provides are equally important. Choosing the correct component can make an application much easier for a user to understand.

## Key Takeaways

1. Java provides a structured Collections Framework that makes commonly used data structures easier to implement and manage.

2. Unmodifiable views can be used when other parts of a program should be able to access data without changing it.

3. JavaFX events follow a defined path through the scene graph, with capturing and bubbling taking place in different directions.

4. Different UI components are designed for different kinds of user interaction, so choosing the right component is an important part of interface design.

5. Responsive layouts allow graphical interfaces to adjust according to the available space instead of depending completely on fixed positions.

6. Master-Detail layouts help applications display large amounts of information without showing everything at once.

7. JavaFX can interact with web content through WebView and WebEngine, showing how desktop interfaces can be connected with browser-based content.
