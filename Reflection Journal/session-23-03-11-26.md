## Session Content

In this session, we learned about how digital images are stored inside a computer and how the colour information of each pixel is represented in memory. In the previous session, we focused on processing images, but we went deeper into understanding how the actual pixel data is stored and read.

We started with the concept of pixels and their colour representation. Each pixel contains colour values, usually represented using RGB, which stands for Red, Green and Blue. Each colour channel uses 8 bits or 1 byte and can have a value between 0 and 255. This means that RGB can represent around 16.7 million different colours.

We then discussed the difference between RGB and RGBA. RGB uses three channels, while RGBA includes an additional Alpha channel that controls transparency. The Alpha value also ranges from 0 to 255, where 0 means completely transparent and 255 means fully opaque. This helped me understand how transparency is represented along with the normal colour values.

Another topic discussed in session was how images are stored in memory. An image is made up of rows and columns of pixels, but the computer can store all these pixel values in one continuous one-dimensional array. We learned how to calculate the starting position of a pixel using the formula `(i * n + j) * 3` for RGB images. For RGBA images, we use 4 instead of 3 because each pixel contains four bytes. This also helped me understand how the size of an image depends on its dimensions and the number of bytes used for each pixel.

After that, we discussed byte ordering and different ways of arranging colour channels, such as RGBA, BGRA and ARGB. The actual pixel colour remains the same, but the order in which its colour values are stored changes. This is important because a program needs to know the correct channel order to display the image properly.

We also learned about endianness, which explains how bytes are arranged when storing a value that uses multiple bytes. In little-endian format, the least significant byte is stored first, whereas big-endian stores the most significant byte first. We used the example `0x12345678` to understand how the same value can be stored in two different byte orders.

Then we discussed network byte order, which follows the big-endian format. I understood that channel ordering and endianness are two different concepts, even though both deal with the arrangement of bytes. If a program interprets the data using the wrong order, it can produce incorrect values or display colours differently.

## Real-World Applications Explored

Pixel representation and channel ordering are important in image editing and graphics applications. For example, if an application expects RGBA data but receives BGRA data, the red and blue colour channels may get swapped, causing the image to display incorrect colours.

Different programming environments also use different image formats and channel arrangements. For example, HTML Canvas works with RGBA pixel data, while Java's BufferedImage supports different image types such as ARGB and BGR.

Endianness is also important when transferring data between computers and storing information in files. Network protocols use big-endian byte order so that systems can interpret the transmitted data consistently. Image formats also need to specify how their data should be read to avoid incorrect interpretation.

## Key Takeaways

1. A pixel stores colour information using different channels. RGB uses three bytes per pixel, while RGBA uses four bytes because it includes an additional Alpha channel for transparency.

2. Images can be stored as a continuous one-dimensional array of bytes. The formula `(i * n + j) * 3` helps calculate the starting position of a pixel in an RGB image.

3. Channel ordering determines how colour values such as Red, Green, Blue and Alpha are arranged. Common formats include RGBA, BGRA and ARGB.

4. Endianness determines the order in which bytes of a multi-byte value are stored. Little-endian stores the least significant byte first, while big-endian stores the most significant byte first.

5. Network byte order follows the big-endian format. Understanding both channel ordering and endianness is important to ensure that image data and other information are interpreted correctly.
