# Session 14 - Project Testing and Presentation Preparation

**Session Date:** 29/09/26

---

## Session Content

Session 14 focused mainly on testing our completed JavaFX project and preparing for our presentation. After completing the major development in the previous session, we ran the application and checked whether its different features were working as expected.

We tested the splash screen, loading messages, progress bar, last-opened time, and the transition to the main application. We also tested saving notes, reopening the application to check whether the notes were retained, and the warning that appears when trying to close the application with unsaved changes.

After testing the application, we started working on the PPT. We discussed the key points to include, selected relevant screenshots, and began organizing the explanation of our project's objective, features, FXML structure, and overall functionality.

## What Else I Remember

This session helped us view the project from a user's perspective rather than focusing solely on the code. While testing, we followed the actual sequence a user would go through, from opening the application to writing and saving a note, and finally closing it.

We also realized that testing is important even after the main development is complete, because some issues only become noticeable when the application is used in full.

## Visual Observations

The final application showed the complete flow from the splash screen to the main notes screen. We also had screenshots of the working application to use during the presentation to explain the project.

## Code / Implementation Done

No major new features were added during this session. Instead, we tested the existing implementation and checked the interaction between the different components.

The main development was already completed in Session 13, so this session focused more on validating the project than on adding new features.

## What I Understood Well

I understood the importance of testing an application as a complete system. A feature may work correctly on its own but still create problems when it interacts with other features.

I also understood that presenting a software project requires more than showing the final interface. We need to explain what the application does, how FXML and Java were used, and how the different features work together.

## What I Found Challenging

The main challenge was checking all the possible user flows rather than only testing the normal case. For example, we had to specifically check what happened when notes were changed but not saved before the application was closed.

Organizing the project information for the PPT was another challenge because we had to decide which technical details were important enough to explain clearly without making the presentation unnecessarily complicated.

## Connections to Prior Sessions

This session brought together the work from Sessions 12 and 13. The basic FXML structure created in Session 12 and the major functionality implemented in Session 13 were tested as one complete application.

The testing was also connected with the earlier JavaFX concepts because we had to verify that the interface, controllers, and application logic were communicating correctly.

## Real-World Applications Explored

Testing is an important part of real-world software development because applications need to be tested in different scenarios before they are released to users. Features such as automatic saving, loading previous data, and unsaved-change warnings are also common in real productivity applications.

## Key Takeaways

1. Testing the complete application is necessary after implementing individual features.
2. Different user scenarios should be checked before considering a project complete.
3. FXML, controllers, and Java logic need to work together correctly for the application to function properly.
4. A good presentation should explain both the application's purpose and its implementation.
5. Testing and reviewing the project helped us understand our own implementation more clearly.
