# Session 15 - Functionality, Generics and JavaFX Shapes

**Session Date:** 01/10/26

---

## Session Content

Session 15 was a bit different from our usual classes as we first had mock presentations for some of the groups including our group. This gave us an idea of how the actual project evaluation will happen. We got to see how a project should be presented and what kind of things the faculty would look for during the evaluation. It also showed me that presenting a project is not only about showing its features but also about explaining the project properly.

One thing that stood out to me was the difference between functionality and features. Functionality is basically whether the main purpose of the software actually works correctly, while features are the additional things we add to the project. I understood that having multiple features is not very useful if the main functionality is not reliable.

After the presentations, we discussed generic programming in Java. I understood that generics help us avoid writing almost the same code again for different data types. Instead of creating separate classes or methods for each type, we can use a type parameter and reuse the same logic. This makes the code easier to maintain and also reduces unnecessary repetition.

We then connected these ideas with JavaFX. We discussed the Shape class and how different shapes such as Rectangle, Circle, Line and Ellipse are related to it. Since these shapes share common properties, they can be handled through the common Shape type. We also discussed properties such as fill, stroke, stroke width and opacity.

---

## What Else I Remember

The discussion about JavaFX also introduced the difference between Shape objects and the GraphicsContext approach. Shape objects are part of the scene graph and remain as objects that we can modify through their properties. GraphicsContext works more like direct drawing, where commands are given to draw something on a Canvas. I found this difference useful because it showed that JavaFX provides more than one way to create graphics depending on what the application needs.

The mock presentation at the beginning also made the rest of the session feel more connected to our own project. Instead of only learning concepts separately, I could relate them to the things we are currently building.

---

## What I Understood Well

Generics was one of the topics I understood quite well because the main idea is about reusing the same code for different types. For example, instead of making one class for integers and another similar class for strings, we can create one generic class and specify the type when we use it. This makes the code cleaner and avoids having multiple versions of almost the same logic.

I also understood the JavaFX Shape hierarchy better after seeing how different shapes share common properties. A Circle and Rectangle are different shapes, but both can have properties like fill, stroke and opacity. This helped me connect the concept of inheritance and polymorphism from earlier sessions with something practical in JavaFX.

## Connections to Prior Sessions

The discussion about generics connected with the OOP concepts we learned in the earlier sessions, especially inheritance, polymorphism and code reuse. It made me realise that writing reusable code is not only about inheritance. Generics provide another way to write one piece of logic that can work with different types.

The JavaFX discussion also connected with our earlier Java 2D sessions. Previously, we used drawing methods to create shapes, while JavaFX allows us to create shape objects and work with their properties. Seeing these two approaches together helped me understand the difference between directly drawing something and creating an object that remains part of the graphical application.

---

## Real-World Applications Explored

Generics are commonly used in Java applications, especially in collections such as `List`, `Set` and `Map`. The same collection structure can work with different types of data without needing to write separate implementations.

The idea of common Shape types can also be useful in applications involving graphics. For example, a drawing application can contain circles, rectangles and lines together and still handle them using their common properties. This makes it easier to manage different graphical objects in the same program.

---

## Insights

The functionality versus features discussion was probably the most useful part of the session for me. While working on a project, it is easy to focus on adding more things because it makes the project look bigger. But this session made me realise that the important thing is first making sure that the main functions work properly. A smaller project that works reliably can be better than a project with many features that do not work properly.

I also liked the idea behind generics because it showed me that code reuse is not just about reducing the number of lines. Keeping similar logic in one place also makes it easier to fix and improve the code later.

---

## Key Takeaways

1. Functionality and features are different, and the main functionality of a project should work properly before focusing on extra features.

2. Generics allow the same class or method to work with different data types, which makes code more reusable and easier to maintain.

3. JavaFX shapes such as Circle, Rectangle, Line and Ellipse share common properties through the Shape class.

4. JavaFX Shape objects and GraphicsContext provide different approaches to drawing, with shapes being part of the scene graph and GraphicsContext drawing directly on a Canvas.

5. The mock presentation helped me understand that explaining and presenting a project properly is also an important part of project evaluation.
