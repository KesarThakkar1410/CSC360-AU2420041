# Session 13 - Major Project Development and Implementation

**Session Date:** 17/09/26
---

## Session Content

Session 13 was mainly focused on the major development of our CSC360 group project. After setting up the basic structure and splash screen in the previous session, we implemented the main functions of our JavaFX application.

We completed the splash screen by adding a progress bar, loading messages, the last-opened time, and an option to close the application while it was loading. We then created the main application screen where users could write notes.

The main focus was on implementing the note-related functionality. We added the ability to save notes and load previously saved ones when the application is reopened. We also implemented a warning for unsaved changes when the user tried to close the application. Finally, we connected the splash screen to the main application and improved the overall layout and appearance.

## What Else I Remember

This session felt significantly more like actual application development than the previous one. We were able to see the different parts we had planned come together into a single working application.

Since several features had to work together, we tested the application repeatedly during development. This helped us catch small issues and make corrections rather than waiting until the very end.

## Visual Observations

By the end of the session, the application had both its splash screen and main notes screen. The splash screen displayed application information and loading status, while the main screen provided space to write and save notes.

## Code / Implementation Done

Most of the project's features were implemented during this session. We connected the FXML components with the Java controllers and application logic, implemented note saving and loading, and added the unsaved-changes protection.

We also connected the splash screen to the main screen so that the application followed the intended flow from loading to the actual notes interface.

## What I Understood Well

I understood better how different JavaFX components and event handling work together. For example, saving a note was not just about creating a text area; the application also needed logic to store and retrieve the content later.

I also understood how the controller acts as a link between what the user sees in the FXML interface and what the application actually does.

## What I Found Challenging

The main challenge was making sure that the different features worked together without affecting one another. The save, load, and unsaved changes features all depended on the application's state, so testing each part individually was not enough.

We had to run the entire application and verify the actual user flow to ensure everything behaved as expected.

## Connections to Prior Sessions

This session was a direct continuation of Session 12. The basic FXML structure and splash screen created in the previous session became the foundation for implementing the complete application.

The JavaFX and controller concepts discussed earlier in the course were also applied more practically while connecting the interface with the application's functionality.

## Real-World Applications Explored

The note-saving feature is similar to how many real applications preserve user data, so the notes remain available when the application is reopened. The unsaved-changes warning is also commonly used in editors and productivity applications to prevent users from accidentally losing their work.

## Key Takeaways

1. JavaFX features become more useful when interface components and application logic are properly connected.
2. Saving and loading data requires both a user interface and supporting application logic.
3. Features should be tested together, not only individually.
4. FXML provides a clear way to organize the application's interface separately from its behavior.
5. Group communication is important when multiple features are being developed as one application.
